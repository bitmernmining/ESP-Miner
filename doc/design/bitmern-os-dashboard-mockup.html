What changed vs. current AxeOS

  • One hero metric. Hashrate leads with a sparkline; today it's an equal-weight card in the grid.
  • Status row surfaces online/pool/best-diff/uptime at a glance — currently buried in separate cards.
  • Arc gauges replace bare progress bars for temp/fan/voltage, with green/amber/red zones.
  • Every value shown is a real field from info$ — hashRate, errorPercentage, bestDiff, temp, fanspeed, voltage, poolDifficulty.
  • Pool user shown truncated, matching the existing sensitive-data masking directive.
  • Use the Dark / White toggle above to compare both theme directions, and Mobile / Web to see the same cards reflow into the existing AxeOS sidebar layout at desktop width — no separate portal, same on-device page.

Why a detail view

  • Tapping any health gauge on the dashboard opens this screen — same data, more room, one metric at a time.
  • Zone bands on the arc are the same green/amber/red thresholds already hard-coded in home.component.html (70°C danger line, etc.) — just drawn instead of implied by a red warning string.
  • History sparkline uses a rolling client-side buffer — no new firmware storage, no added heap.
  • Still just cards and SVG paths; no charting dependency beyond what app-chart already pulls in.

Every card in the plan gets a designed state instead of a blank space or raw error text. These four cover the cases home.component.html currently handles ad hoc (e.g. the power_fault branch, the empty pool block) plus first-run, unified under one visual language.
